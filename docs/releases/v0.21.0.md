Gateway v0.21.0: the build-tagged acquisition fixture, a test aid that ordinary builds and the release archives exclude, is held to its own marker and to a fixture-only connection store before it reads anything, and each refusal of its builder is tested; a test holds the page request schema's closure. Nothing an operator runs changes.

## What an operator must do

- **Nothing.** Receipt version 3, engine configuration version 10, the connection catalogs, the frozen conformance corpus and the contents of the release archives are unchanged. Every change is in test files, in fixture code under the `gateway_acquisition_fixture` build tag, or in the release tooling's refusal of a fixture-tagged build record. An acquisition sends byte for byte the request it sent under v0.20.0 and mints the same receipt.
- **If you build the acquisition fixture for your own tests**, build it with its builder (`adapters/testdata/acquisition-fixture/build.py`), which stamps the `fixture.<revision>` version: a tagged program without that stamp now refuses every request as `fixture-build-required`, before it reads its input or opens a store. Point it only at a disposable store: its search bridge refuses any connection that is not a `tavily` connection holding the fixture credential, as `fixture-store-required`, before anything is charged.

## The acquisition fixture held to its own marker and store (#300, closes #294)

- The marker is checked first, for both roles, before standard input is read or a connection store is opened; a test gives an unmarked build an input that counts reads (it stays at 0) and a state directory that must stay empty.
- The search bridge and its description refuse any connection that is not `tavily` with the fixture credential, before the daily allowance is charged; the test holds a non-fixture key at a daily limit of 1 to zero requests, and refuses the fixture credential under `google-grounding` and under an unknown provider.
- The builder's refusals each have a test: a tag that does not verify, a tag naming another commit, a dirty checkout without the flag, an output path inside the checkout or already existing; the `git` stand-in asserts the refs it is called with. The `--principal` check has a test.
- `build/release_archives.py` refuses a build record that carries `-tags=gateway_acquisition_fixture`, in any comma list; an official record carries no tags, so no release is refused by it.
- Both findings came from the cross-vendor audit of #290 recorded on that pull request (#294).

## The page request schema's closure held by a test (#299, closes #292)

- `adapter-web --describe-research` publishes a closed page request schema. Its test read `additionalProperties` into a Go `bool`, so a missing member passed as `false`; it now decodes a `*bool` and requires the member present and exactly `false`. Deleting the member, setting it to `true` or to a schema object each fails the test. From the cross-vendor audit of #287 (#292).
