# v0.32.0

This release adds a read-only Cloud Asset Inventory source, for reading a project's resources
and IAM policies as attested state that a pack compares against the configuration intended for
it: configuration drift (#488; ADR-0039 and its two Amendments). It is an engine source of a new
binding shape, `gcp-asset`, served by a new adapter, `adapter-gcp-asset`, at engine configuration
version 29. The source is read-only by check, not by its scopes alone: before a token is used,
at the start and with every token after it, the adapter asks the platform which of a fixed list
of write permissions the credential holds on each configured project, and a credential it
cannot show to be read-only is refused, which closes the source until the engine restarts. Each
acquisition is one page of one list call; the paging is the caller's, and the payload is not
kept by default. Receipts, seals and stores keep their form, and nothing about the other shapes
changes. The release review's fixes are in #493: among them, only an answer of the platform
refuses the check, and a check that brought back no answer fails one acquisition and closes
nothing. The release tag is also the milestone; #488, the line's issue, is the one closed in it.
The implementation rows are
[#487](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/487),
[#490](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/490),
[#491](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/491) and the pre-release batch
[#493](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/493).

## Changes for operators upgrading from v0.31.0

1. **A read-only Cloud Asset Inventory source, at engine configuration version 29** (#491;
   ADR-0039 and its Amendments). Nothing changes until it is configured. The steps are in
   [`docs/design/engine-config.md`, "A read-only Cloud Asset Inventory source (engine version 29)"](https://github.com/Judgment-Pack/judgment-pack-gateway/blob/v0.32.0/docs/design/engine-config.md#a-read-only-cloud-asset-inventory-source-engine-version-29),
   and the binding's members in
   [`adapters/README.md`, "adapter-gcp-asset"](https://github.com/Judgment-Pack/judgment-pack-gateway/blob/v0.32.0/adapters/README.md#adapter-gcp-asset).
   - Raise `engineVersion` to `"29"`. The binding's live operation, its only operation, is of
     shape `gcp-asset`: `parents` (projects only, each `projects/<project-id>`; a folder is
     refused at load, #489), `assetTypes` (an explicit list, each with a projection), and
     `contentTypes` (`RESOURCE`, `IAM_POLICY` or both); optionally `members: "count-users"`.
   - The platform names `credentials.live.tokenSource`, `{"kind": "metadata"}` or
     `{"kind": "key"}` (item 3). `artifact` defaults to keeping no payload; `"retained"` keeps
     them. `scope`, as on any platform, fixes the source to at most one scope identifier.
   - Refused by name at load: `write: true`; no `tokenSource`, or one on another shape's
     platform; a `tokenStep`, a `grant` or an `endpoint`; an `environment` that sets
     `ADAPTER_GCP_ASSET_SEALED_TOKEN`.
   - `gateway connect` does not write a platform of this shape: write its entry by hand.
2. **Grant the source's account `roles/cloudasset.viewer` on each configured project, and
   nothing more; enable two APIs.** The adapter calls the Cloud Asset API (the list call) and the
   Cloud Resource Manager API (the write check), and both must be enabled for the credential. A
   disabled API answers `403`: on the write check that refuses `credential-can-write` with no
   permission named, at the start or on a refresh; on the list call it is an upstream error.
3. **Two narrow tokens, and the list token held sealed.** The adapter requests one token of
   scope `cloudasset`, for the list call alone, and one of scope `cloud-platform.read-only`, for
   `testIamPermissions` alone; `cloud-platform` is never requested. The scopes each was granted
   are read, and anything beyond the one requested, but for the identity scopes `openid`,
   `userinfo.email` and `email`, is refused `credential-scope-unknown`.
   - `metadata`: the metadata server of the platform's own compute, no key on disk; the live
     credentials file holds `{"sealKey": "<64 hex digits>"}`. `key`: a service account's key in
     that file, the least preferred. Federation is withheld (#492).
   - The signer never reads a credential or a token in the clear. The adapter answers the list
     token sealed with AES-256-GCM, and the signer hands it to the next acquisition in
     `ADAPTER_GCP_ASSET_SEALED_TOKEN`. SECURITY.md says what that seal does not bound.
4. **A refusal closes the source until the engine restarts** (SPEC.md §6, "A read-only refusal,
   shape `gcp-asset`").
   - The adapter exits **9** with `{"refused": {"reason", "subject"}}`. The reasons are
     `credential-can-write` (a permission of the write list granted on a configured project, or
     an answer that is neither a grant nor none: a status other than 200, a redirect, a body out
     of form), `credential-bound-at-resource` (an `IAM_POLICY` page binds the source's own
     principal, `allUsers` or `allAuthenticatedUsers` to a role outside the read-only list) and
     `credential-scope-unknown`. A report out of its form is a refusal all the same.
   - At the start, a refusal refuses the start, before anything is served. After it, the
     acquisition, and every acquisition of the source after it, is answered `400` with the
     refusal's sentence, nothing run, minted or retained; the engine's stderr says the closure
     once, with where it was met, and `/posture` reports the source `closed`, without the subject.
   - **A check that gets no answer exits 1 and closes nothing.** Where a call brought back no
     answer (the adapter's time ended, the request's own 15 seconds did, or the connection failed
     before the platform answered), no token is sealed: the start is refused, or that acquisition
     fails as a failed source, and the next acquisition checks again. A grant another call
     answered still refuses.
5. **What the check does not see.** The write list (`gcp-asset-write-list/2`, in the adapter's
   README) is fixed, not complete. The resource-binding check reads the `IAM_POLICY` pages
   callers request and makes no call of its own: a platform that serves no `IAM_POLICY` says
   `resource-bindings: unchecked`. It does not see a grant through a group, a domain or a
   principal set, nor a binding on an asset type the source does not serve or on a page no
   caller reads. A custom role is never on the read-only list.
6. **`/posture`** adds the line `read-only-credentials` (`enforced` where every `gcp-asset`
   source serves `IAM_POLICY`, `partial` otherwise) and `readOnlySources`, one entry per source
   within the caller's reach: its token source, `writeCheck`, `state`, `artifact`,
   `resourceBindings` and `refusal`. The line's counts (sources, those serving `IAM_POLICY`,
   those closed) are of the sources the caller reaches; its state is judged over every source.
7. **One page per acquisition.** A request is `{"parent", "contentType", "assetTypes",
   "pageToken"?, "pageSize"?, "readTime"?}`, and makes one `assets.list` call. The next page
   token comes back as the platform wrote it, or `null`, and is never followed. Each asset type's
   `resource.data` is cut to an allow-list before the digest is taken: no environment value of a
   Cloud Run service is carried, only a variable's name and a secret's name and version.
   IAM members are carried as written, or, with `count-users`, `user:` members as a count.
8. **The engine image and the release archives carry `adapter-gcp-asset`**, beside the other
   adapters, at `/usr/local/bin/adapter-gcp-asset` in the image.
9. **Fixed from the release review** (#493).
   - Only an answer of the platform refuses: a check that brought back no answer exits 1, never
     9, and closes nothing (item 4). Before, a slow platform or a dropped connection closed the
     source until a restart.
   - The gateway hands the adapter `--timeout`: what its own deadline for the run leaves, less a
     margin of five seconds, or of half that time where half is less. The adapter asks the
     configured projects at most eight at a time.
   - A role outside the read-only list granted at a served resource to `allUsers` or
     `allAuthenticatedUsers` is refused `credential-bound-at-resource`.
   - `/posture`'s `read-only-credentials` counts are of the sources within the caller's reach.
   - SPEC.md §6 and SECURITY.md describe the shape, the exit-9 report and the sealed token; the
     adapter's README names the role and the two APIs. An unused build-tag file is removed.

## Decisions

- ADR-0039: a read-only Cloud Asset Inventory connection for configuration drift, read-only by
  check, one page per request, the payload not kept by default; the gateway judges nothing.
  Accepted under the maintainer's standing delegation; the maintainer may revise it.
- Its first Amendment (#490): an engine source of shape `gcp-asset` at engine configuration
  version 29, not a custody connection, so the scope identifier, the caller's reach, the
  payload not kept, the start report and `/posture` all apply; projects only; two narrow
  tokens; the adapter's own token sources.
- Its second Amendment (#493): only an answer of the platform refuses; a check that could not
  finish exits 1 and never closes the source; the gateway passes `--timeout`; public members
  are refused as the source's own principal is.

## What this release does not establish

- That a credential is read-only in every respect: the write list is fixed, not complete, and a
  grant through a group, a domain or a principal set, or on an asset type the source does not
  serve, is not seen (item 5).
- With caller scopes checked, `read-only-credentials`' `enforced` or `partial` is judged over
  every source, so a caller can learn one bit about the sources of other scopes; open as #494.
- Folder parents (#489). Federation with impersonation is withheld: not in this release (#492).
- What the platform answers has not been confirmed in a live run: the form of an expired page
  token's answer (read as `410` on a request that sent one), the scopes each token source
  reports as granted, the Cloud Run resource form (both are projected), whether every
  permission of the write list is reported at project level, and which project's API enablement
  applies to each call. Every test runs against in-process servers and hand-written fixtures.
- Not in this release (#492): a throttled list call (`429`, `503`) is not mapped to
  a throttled source; a closed source's `400` names the refusal's subject, where `/posture`
  does not; no refusal emits an event; a platform's `environment` may set `SSL_CERT_FILE` or
  `HTTPS_PROXY`; no test runs the built adapter under `gateway serve`.
- Earlier open items stand: #478, #483, #440, #444, #447, #474 and #450.
