# v0.23.0

This release adds customer MCP registration, retained descriptor provenance,
source sandbox policy and posture, and action reconciliation after uncertain writes.
The release tag is also the milestone. The four implementation rows are
[#348](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/348),
[#349](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/349),
[#350](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/350) and
[#351](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/351).

## Customer bindings and descriptor evidence

A customer binding registers a pinned container image, remote MCP endpoint or
local command through the existing source declaration. The operator declares each
allowed tool's operation and effect. Missing declarations and contradictions with
server annotations refuse registration. A version-3 descriptor snapshot pins the
complete approved tool descriptors; changed descriptors and unapproved tools
refuse acquisition before dispatch.

Registration retains descriptor bytes and a separately signed statement before
publishing configuration. Engine configuration 12 introduces per-operation
`descriptorStatements`; capture preserves newer configuration versions. Receipt-v3
acquisitions can reference the retained provenance. Both receipt readers verify its
canonical bytes, signature, binding and signing-key ordering. Existing receipts
without these members make no new provenance claim. A gateway signature establishes
byte lineage and the gateway's capture assertion, not the customer's honesty or
the truth of a descriptor.

## Source policy and honest posture

Engine configurations 13 and later wrap every configured source adapter and its
descendants with the trusted `adapter-sandbox` helper, including registration
checks. The `sandbox` settings object is optional; omitting it still selects
workspace-write by default. Permission
presets expand into policy-version-2 settings; the operator's filesystem mode is
separate from tool-effect approval. Keep the policy, credentials, signing material
and approval evidence outside a source's writable workspace.

Linux uses bubblewrap or a partial Landlock fallback; the latter does not confine
filesystem metadata changes. macOS uses Seatbelt. Local customer commands default
to workspace-write, and read-only and explicit full-access modes are available
where supported. Posture records each program's backend and measured limits.
The optional enclosing-boundary flag is an operator assertion, not independent
proof of enforcement. Container-daemon authority, network effects and readable
host data are outside this filesystem write-policy claim.

**Windows restricted local commands are unavailable.** Read-only and
workspace-write refuse before execution, including registration and acquisition
under an existing approval. In engine versions 13 and later this also refuses
the wrapped adapters for remote and container sources unless the operator
explicitly selects full access. Posture reports `backend: none`, `state: not-enforced`
and the unavailable-backend reason. The experimental token/ACL implementation is
not shipped. Explicit operator-selected `danger-full-access` remains unrestricted;
there is no automatic fallback and no sandbox job-containment guarantee in that
mode. Full access does not enable keyed action dispatch on an unsupported host.
Remote and container policy paths retain their own documented limits.

## Executable binding and sandbox honesty

A pre-release batch closes the review findings dispositioned on #348 and #350.
The fix commits are Claude's, as are the stack merges and the re-read of #350, so
for that material the review is a same-vendor check under the regime's exception
for changes that implement dispositioned findings, not a cross-vendor claim.

- **`#!` interpreters are bound.** A version-4 approval of a `#!` command now
  carries `interpreters`: each program that runs before the script, by path and
  digest, the program `#!/usr/bin/env NAME` finds on the server's `PATH` included.
  A re-pointed or changed interpreter refuses with `mcp-executable-changed`; an
  `env` line with options or assignments refuses with `mcp-executable-unbindable`.
  Both readers and the shared vectors carry the member. Version 4 is unreleased, so
  no approval changes shape.
- **What is digested is what runs.** On Linux (amd64, arm64) a binary command runs
  from a sealed in-memory copy of exactly the digested bytes, so an in-place rewrite
  after the digest no longer runs. The check report's sandbox reason, and posture's
  customer-command entries, say what is re-checked by path instead, and when.
- **Socket masking and posture.** Bubblewrap masks every listening Unix socket
  bound to a path, the socket `DOCKER_HOST` or `CONTAINER_HOST` names and the
  desktop runtimes' sockets, after the writable binds. A listening abstract socket,
  or a socket list that cannot be read, reports `partial`; Seatbelt is always
  `partial`.
- **Public posture names no path or account again.** `/posture` program reasons
  are fixed sentences; `gateway posture` keeps the detail.
- **A measured failure refuses.** A restricted launch whose probe measured the
  boundary as not holding refuses, and a probe that timed out is not cached.
- **Smaller fixes.** `gateway connect` prints the sandbox mode, backend and state;
  a policy path through a workspace link refuses, and the engine holds the policy
  file's owner and mode at start; Landlock and Seatbelt allow `/dev/null` writes and
  Seatbelt gets a resolved temporary directory; leftover temporary files no longer
  fail a completed call; a FIFO at the command path refuses at once; argv[0] is the
  configured word again; the script operand is the first operand naming a file; the
  server's environment travels in a sealed memory file on Linux; a bubblewrap
  launcher's program interpreter and library search path are held.

Known limits after the batch:

- An acquisition's receipt records no sandbox backend. Under engine version 13
  every launch is bound to the backend its source's posture reports and refuses
  otherwise; the registration check report and `gateway connect` show it.
- A `#!` script, its interpreters, a script operand, and every customer command
  file on macOS and Windows are executed or opened by path after a re-check taken
  immediately before the start; a change after that re-check is not detected. A
  binary's shared libraries, and code an interpreter loads by other means, are not
  bound.
- On Linux the server's `/proc/self/exe` names the copy that runs: under
  bubblewrap a read-only file in the sandbox, elsewhere the sealed memory file,
  whose path a server that re-executes itself by name does not find. A host that
  refuses to execute the sealed memory file refuses the start with
  `sandbox-sealed-exec-refused`.
- A listening abstract socket cannot be masked while the network namespace is
  shared, which every mode does; its presence keeps the state `partial`. A socket
  that starts listening after a launch is not masked, and a server that needs a host
  socket (a name service, a session bus) cannot reach one under a restricted mode.
- On macOS the server's environment, credentials included, still travels in an
  unlinked file in the private temporary directory.
- The policy file's owner and mode are checked at start; a later change by root or
  the signer takes effect after the next restart's probe, as before.

## Uncertain actions

Engine configuration 14 requires a caller-selected `actionKey` on `/act`; older
configurations can opt in by supplying it. Reuse that key for the same intended
action after a lost response. The gateway durably reserves it before dispatch and
never sends that mutation again under the same authority and authenticated issuer
and subject, including across sessions, token renewal and restart. A different
approved request or source configuration under the same key is refused. A new key
is a new action and must not be invented merely to retry an uncertain one.

Binding version 3 declares idempotency and read-back support per write tool, or
explicitly declares unsupported recovery. A retained uncertain action can produce
a separate read-back acquisition receipt linked to that action. A matching key and
the declared committed value report `committed`; other observations remain
`unknown`. Neither outcome authorizes another mutation dispatch. A target's
response remains evidence of what it reported, not proof of its truthfulness.

The shipped write bindings declare no generic recovery guarantee. A binding needs
an explicit pinned target contract to enable read-back. There is no new Drive
write binding; its separate personal storage protocol is unchanged.

Keyed dispatch requires supported Unix file and directory synchronization.
Unsupported hosts refuse before sending a keyed action. Operator backups must
preserve the private `actions/` journal with the store: receipt exports omit it,
and restoring receipts alone does not preserve the dispatch history. Readers of
the new delivery and reconciliation members need this release's verifier support.

## Validation and release gates

The acceptance cases include descriptor and owner-declaration refusal, signed
provenance mutation vectors in both readers, actual filesystem boundary probes,
Windows refusal without execution, and a target that commits then drops its
response. Reconciliation tests cover concurrent repeats, restart, synchronization
failure, changed source policy, unsupported recovery and tampered retained evidence.

The PRs retain exact-head check and independent-review records. Publishing requires
the repository's different-vendor adversarial review and finding dispositions,
required CI at each merge candidate, and release evidence from the tagged main
commit. A local check or same-vendor clean-room review does not replace those gates.
