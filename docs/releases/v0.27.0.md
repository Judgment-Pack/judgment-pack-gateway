# v0.27.0

This release lets a gateway be run as a service that other hosts call. An engine configuration
can listen off loopback once it authenticates its callers and says so (#400), and posture reports
where the gateway listens (#401). A platform can be fixed to an opaque scope identifier that every
acquisition must state and every receipt of it carries under the signature (#420). An `http`
source can obtain its own access token, by a signed client assertion or a federated identity token
(#421). A receipt can stay checkable when the gateway does not hold the payload: a source can be
declared to keep none, and a kept payload can be removed under a signed record (#422). `/acquire`
answers a throttled `http` source with its class and a bounded wait, so a caller can retry, and
paging over a source is stated to be the caller's (#425, #389). An `http` path the client would
send percent-escaped is refused at load (#407, item 1). The release tag is also the milestone. The
implementation rows are
[#416](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/416),
[#417](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/417),
[#418](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/418),
[#423](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/423),
[#424](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/424),
[#426](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/426) and
[#427](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/427).

## Compatibility

| With | What holds |
|---|---|
| An engine configuration of version 18 or earlier | Loads and behaves as before, except an `http` binding whose paths hold a character item 2 names. `connect` raises no file to 19–22: edit `engineVersion` by hand. |
| A gateway of v0.26.0 or earlier | Refuses a configuration of version 19, 20, 21 or 22 by its version. |
| Receipts and stores written before this release | Keep their bytes and verify as before. A receipt without `scope` or `artifact` is unchanged byte for byte. |
| A verifier of v0.26.0 or earlier, Go or verify-ts | Answers `ok` on a well-formed scoped receipt, and on a malformed `scope` member. Reports a payload never kept, and one removed under a record, as `artifact-missing`. It still refuses a receipt changed after signing. |
| A caller of `/acquire` | May now receive `429` or `503` with `Retry-After` from an `http` source (item 7), and must state `scope` for a scoped source (item 4). |
| Judgment Pack Runner | A Runner that retries a throttled acquisition needs a gateway of this release: an earlier gateway answers a throttled source `400`, which a Runner does not retry. A Runner job that states a scope identifier needs a platform fixed to the same one. |
| Posture consumers | Every posture answer changes (item 1). |

## Upgrade

1. Every posture report gives a sixth line, `listener-reach`, after
   `operator-program-confinement` (#416). The report is canonical JSON compared byte for byte, so
   the bytes of every `/posture` and `gateway posture` answer change. Posture is information,
   never a gate.
   - `enforced` on a loopback address; `not-enforced` off loopback with no caller authenticated;
     `partial` off loopback with callers authenticated; `not-applicable` for `gateway posture`
     with no configuration.
   - The line gives the class of the address, never the address or the port. A listener the route
     does not know is taken as reachable.
2. An engine configuration that pins an `http` binding no longer loads when a `paths` entry or the
   endpoint's path would be sent percent-escaped (#417). A path is accepted only when its sent
   form equals its written form.
   - Newly refused in `paths`: `! " ' ( ) * < > [ ] ^ |` and the backtick. In the endpoint's path:
     the same, and the backslash.
   - In its plain form `adapter-http` refuses such a path for `--paths`, `--check-path` and a
     request's path. That includes `%` and characters beyond ASCII, which it accepted before and
     sent escaped.
   - No shipped binding, catalog entry or conformance vector uses a newly refused character. A
     configuration that does must name a path the source serves without them; there is no
     switch that restores the earlier behaviour.
3. engineVersion 19 adds `acceptOtherHostsOverPlainHTTP` (#418), refused by name under 18 and
   below. A `listen` that is not loopback loads only with an `identity` and
   `acceptOtherHostsOverPlainHTTP: true`; either alone is refused, and the error names both.
   - The member beside a loopback `listen` is refused. A not-loopback `listen` beside `witness`
     or beside `mcp` is refused.
   - `listen` is an IP literal and a port, written as the gateway prints them: no name, no zone,
     a wildcard only when written out. It binds in its own family.
   - With an identity every route but `GET /registry` and `GET /publickey` verifies a token.
   - The start writes a `start:` line on stderr, before the readiness line, saying other hosts
     can reach the listener and that a token over plain HTTP can be read and replayed unless TLS
     terminates in front.
4. engineVersion 20 adds a platform's `scope` (#423), refused by name under 19 and below: an
   opaque identifier of 1 to 128 bytes of UTF-8 with no control, invisible, private-use,
   unassigned or noncharacter code point, and no tab or line feed.
   - `/acquire` takes `scope`. For a scoped source a missing scope or a different one is refused
     `400` before any source call, with one fixed sentence that names no identifier
     (`scope: the request's scope does not match the source's`). A scope sent to an unscoped
     source is refused the same way.
   - A gateway with no scoped source refuses `scope` as it does any member `/acquire` does not
     read.
   - The receipt of a scoped source carries the v3 member `scope` under the signature. A source
     without a scope writes none.
   - A scoped platform is refused beside `write: true` and beside the MCP front.
5. engineVersion 21 adds `tokenStep` to a platform's `credentials.live` on an `http` binding
   (#424), refused by name under 20 and below. Its members are `endpoint` and `clientId`, one of
   `privateKey` or `federatedTokenFile`, and optionally `x5t` or `x5t#S256` and `requestScope`.
   - The adapter signs an RS256 or ES256 client assertion, the algorithm taken from the key type,
     or reads the federated token file at each token request, and asks the token endpoint for a
     client-credentials token. Redirects are not followed, and the answer is bounded in size.
   - The token is cached per source and scope, obtained once for concurrent acquisitions and
     renewed shortly before it expires. A token the source refuses is dropped and the acquisition
     fails without a second source call.
   - Each failure gives one fixed sentence that names the source and never the endpoint's
     answer.
   - No receipt member is added. `connect --replace` keeps the step.
6. engineVersion 22 adds a platform's `artifact: "not-retained"` (#426), refused by name under 21
   and below, and refused beside `write: true`. The gateway returns the bytes with the receipt
   and stores the digest only; the v3 receipt carries the member `artifact` under the signature.
   - New offline command, run with the gateway stopped: `gateway remove-artifact --store <dir>
     --seed <file> --registry <file> --authority <authority> --receipt <session>/<index> --by
     <who>`. It compares the stored bytes with the receipt's digest, appends a signed removal
     record to `<root>/artifact-removals.jsonl`, then removes the bytes and prints the record. It
     refuses a receipt that does not verify, an action, and bytes that do not match.
   - `gateway verify --artifacts <dir>` lets a verifier be given the bytes.
   - New observations beside `ok`: `artifact-not-retained` and `artifact-removed`. Bytes gone
     with no record that loads stay `artifact-missing`; wrong bytes, stored or supplied, are
     `artifact-mismatch`, also after a removal.
   - A removal record loads when its line is of at most 4096 bytes and is one JSON object of the
     stated form. A removals file that is not a regular file, a link included, is not read.
   - The export carries the removal records.
   - **Upgrade every verifier of a registry, Go and verify-ts alike, before a source is declared
     `not-retained` or a payload is removed.** An older verifier reports both as
     `artifact-missing`: it fails closed.
7. `/acquire` answers `429` or `503` in the gateway's own error form when an `http` source's
   endpoint, or its token step's token endpoint, answered `429` or `503` (#427). Before, each was
   a `400`.
   - The body is a fixed sentence, for `429`: `{"error":"source failed: the source's endpoint
     answered 429 Too Many Requests; nothing was retained or minted"}`, and for `503` the same
     with `503 Service Unavailable`. Nothing of the endpoint's body or other headers crosses.
   - `Retry-After` is given in whole seconds, from 0 to 3600, when the source stated a usable
     wait, and is absent otherwise.
   - Nothing is minted or kept. The gateway does not retry, wait or queue. Under a delegation a
     throttled call has used one counted call and one use of the grant.
   - An adapter reports throttling by exit status 7 and the report `{"throttled": {"status":
     429, "retryAfter": 30}}`, read strictly and only from the `http` shape. An older adapter is
     answered as before. Every other source failure is answered as before, byte for byte.
   - A client that treats every `/acquire` status other than `200` and `400` as fatal handles
     these two.
8. A verifier implementation answers more of the corpus. It holds 184 store vectors (51 in
   `stores/`, 133 in `v3/stores/`), 53 of them new: the `v3-scope-*` vectors (#423) and the
   `v3-artifact-*` vectors (#426), some of which supply bytes (`suppliedArtifacts`) and state
   observations. The witness, witness recovery and canon vectors are unchanged, and so is every
   earlier vector.

## Listening where other hosts reach it (#416, #418; closes #401, #400)

`serve --listen` (v0.26.0) can listen off loopback and authenticates no caller. The engine form
can authenticate callers and could not listen off loopback. Version 19 lets it, behind two
statements that must both be made: an `identity`, and the acknowledgment that the transport is
plain HTTP. ADR-0025 has the rule. Posture's `listener-reach` tells the three cases apart, so two
posture answers no longer read the same for a loopback gateway and one any host can call.

## A scope identifier (#423; closes #420)

A platform can be fixed to one opaque identifier. The gateway compares it and signs it; it does
not interpret it. SPEC.md §1.2a states the receipt member, and seventeen corpus vectors, signed by
a signer that shares no code with the gateway, hold both verifiers to it. ADR-0026.

## A token step (#424; closes #421)

A source whose API takes short-lived tokens no longer needs something outside the gateway to
refresh a bearer file. The signer process holds the token only as a sealed value it passes back
to the adapter. A test searches responses, the posture output, logs, the store and the registry
for the token, the assertion, the key and the federated token. ADR-0027.

## Payloads the gateway does not keep (#426; closes #422)

Two ways, both stated in SPEC.md §1.3a and §6 and in ADR-0028. A source declared `not-retained`
never has its payload written, and its receipt says so under the signature, so a verifier tells
"never kept" from "missing" without trusting the store. A payload that was kept can be removed
later, and the signed record of the removal (which receipt, the digest, when, by whom) is what
lets the receipt keep verifying.

## A throttled source, and paging (#427; closes #425, #389)

ADR-0029. The gateway performs one receipted acquisition per request and keeps no cursor for a
generic source: a caller pages with its own cursor, and each page is its own receipt.
`docs/design/engine-config.md` has a worked example of that loop and of where the throttling
answers fit it.

## What this release does not establish

- A listener off loopback is plain HTTP. There is no TLS in the gateway; a token sent to it can
  be read and replayed unless TLS terminates in front. No rate is limited.
- A scope identifier is a label the gateway compares, not an authorization: any admitted caller
  that names the scope is served. Sessions, seals and registry lines carry no scope, and no
  listing is filtered by it. A scoped platform cannot write and is not served by the MCP front.
- The token step was tested against a loopback stub token endpoint only. The token endpoint is
  checked against the system roots. The federated mode still requires the live credentials file
  to exist, though nothing from it is sent.
- A removal record states that the key holder recorded a removal. It does not establish that the
  bytes are gone from every copy, nor who ran the command beyond what `--by` was given.
- A `not-retained` receipt establishes what digest was returned. Whoever needs the bytes later
  must have kept them.
- The gateway reports a throttled source; it does not retry, and it does not page. `Retry-After`
  is the source's statement, bounded, not a promise.
- No engine image is published by this release, and the source sandbox's needs in a container
  are as v0.26.0 documented them (#378, #385, now in the next milestone).
- `adapter-http`'s own endpoint check does not hold the endpoint's path to item 2's rule in the
  plain form; only the engine's does (#428). Items 2 and 3 of #407 stay open.
- A throttled token endpoint is answered with the sentence that names the source's endpoint
  (#428). The status and the wait are right.
- The registry is locked only on Unix, as before.
