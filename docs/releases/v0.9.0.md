Two kinds of change. A decision policy can now require the record it relies on to be signed by a runtime key it trusts. And the engine refuses to start where another user could replace what it relies on: the decision records, the seed and credentials it follows through links, and the adapters it launches. A gateway configured as before keeps its receipts and policies, but **it may now refuse to start**; see what an operator must do.

## What an operator must do

- **To keep a policy as it is:** nothing. A policy without `requireSignedRecord` holds a write as before, and engine configuration versions 1 to 4 are read as before. Receipts minted under such a policy are unchanged.
- **Before updating, check the engine's start-up refusals.** A configuration `v0.8.1` accepted may be refused when:
  - the **decision-record directory**, anything beneath it that the walk reads, or a directory on the way to it, can be written by anyone but root, the signer and the directory's owner. Make the directory and what is in it writable by its owner alone (`chmod -R go-w`). There is no override;
  - an **adapter** is a script (`#!`), is not a native executable of this host, is missing, or could be replaced by another user. Install the adapters as root's, for example `sudo install -o root -m 0755 adapter-airbyte adapter-mcp /usr/local/libexec/engine/`, naming that directory as `adapters`; or run the signer as the user who owns them. An install another user owns, such as a Homebrew prefix or another user's `~/go/bin`, is refused even with `0755` files. A missing adapter now stops start-up, where before it failed at its first launch;
  - a **link to the seed or to a credentials file** is owned by another user, or passes through a directory others can write. A mounted secret whose links root owns, under protected directories, is followed and accepted.

  The engine image's layout passes all of these. Each refusal names the path, its owner or mode, and why.
- **To require signed records:** give a write tool's policy `requireSignedRecord`, a list of the runtime's Ed25519 public keys (as `jpack audit key public` prints them), and declare engine configuration version `"5"`. The runtime that writes the records must sign them, which needs Runtime `v0.26.0` or later with a signing key. A gateway earlier than this release refuses a version-5 file.
- **Verifiers:** an action receipt minted under such a policy carries `decision.recordBytes: "exact"`. A verifier of an earlier gateway tolerates the member, but reads the record with one trailing carriage return stripped. So for a record with a carriage return before its newline, it can answer differently from this release, which reads the exact bytes.

## A write held to a signed record (#201, ADR-0012, closes #198)

Before this release, a decision policy held a write to any well-shaped record in its directory. A file written by hand passed the strictest policy (#195). [ADR-0012](https://github.com/Judgment-Pack/judgment-pack-gateway/blob/v0.9.0/docs/adr/0012-hold-a-write-to-a-signed-record.md) adds `requireSignedRecord`.

- **The new step, `policy-signed`,** comes after `record` and before anything else in the record is compared. It requires a readable line in the runtime's signature sidecar, `signatures.jsonl` beside the record. That line must name the record's `trail` and `sequence`, carry the SHA-256 of the record's exact bytes, and verify under one of the policy's keys. Verification follows the runtime guide's rule, "Record signatures, exactly", implemented independently.
- **Keys:** small-order and non-canonical public keys are refused at configuration, because Go's `crypto/ed25519` accepts forged signatures under them.
- **Rotation:** no key-rotation line is followed. A key counts only because the policy names it. To rotate, add the next key to the policy first, and remove the old one once no record it signed is still waiting to be acted on.
- **The record is found by its exact bytes.** The receipt says so in `decision.recordBytes`, and the verifier reads such receipts the same way (SPEC §1.2a, §4 steps 6 and 8). Six corpus vectors cover it.
- **The walk reads by handle.** It holds the decision-record root and every directory beneath it by identity, so a directory replaced during a walk is not followed.

What it establishes: a writer who cannot use a trusted key cannot satisfy the policy with a record written by hand. What it does not: anything against the operator, who holds the key.

## Start-up refusals (#202, closes #195; #204, closes #203)

- **The decision-record directory** (#202). As above. A link at its path must be owned by root, and the directory the link sits in is held too.
- **The seed and credentials files** (#202) are reached component by component from the root:
  - every link must be owned by root, or, for the seed, by the signer;
  - every directory is held: the one each link sits in, and every ancestor of each link's target;
  - at most 32 links are followed;
  - the resolved path is the one opened.
- **Adapters** (#204). Each adapter a source launches is found once at start-up, under `adapters` or on the engine's `PATH`, and its path is walked the same way.
  - The file must be owned by root or the signer, writable by nobody else, and a native executable of this host. On Linux, `debug/elf` must read it as `ET_EXEC` or `ET_DYN` for the host's machine; on macOS, `debug/macho` must read it as `MH_EXECUTE` for the host's CPU, or as a universal file holding such a slice. A dynamic executable's loader is held like the adapter.
  - The source launches the resolved path.

What these checks are: a check of owners and modes at start-up. They hold while the files and their directories keep that protection, and only against access opened after it was in place. A descriptor opened for writing before then, or an owner or mode changed later, is not seen. They assume the files were installed, by root or the signer, from a source they trust. The format check parses headers; it is not proof that a file runs. The shared libraries a loader finds are not held, so adapters are best linked statically, as the image's are. An ELF's OS ABI is not checked.

## Review

Each change went through cross-vendor review, recorded on its pull request with a disposition for every finding:

- **#201:** three rounds. The second needed two class fixes: a walk that reads only through handles held from its root, and the `recordBytes` receipt member.
- **#202:** three rounds. The second found that refusing every seed link would stop mounted secrets, so links are now resolved and held instead.
- **#204:** three rounds. They led to refusing scripts, and to structural format validation with Go's own parsers.

[docs/releasing.md](https://github.com/Judgment-Pack/judgment-pack-gateway/blob/v0.9.0/docs/releasing.md) says how a release is made and what each check does not establish.
