Gateway v0.19.0: the web-search adapter holds each provider's arguments to one table before anything is sent or charged, refuses every other argument by name, and describes its request and result as versioned schemas; Tavily searches can be restricted to domains and to a time range. A build-tagged acquisition fixture lets consumers exercise page and search acquisitions without live accounts; it is not in the release archives.

## What an operator must do

- **Nothing for existing configurations.** An acquisition without the new arguments sends byte for byte the request it sent before and mints the same receipt; receipt version 3, engine configuration version 10, the connection catalogs and the frozen conformance corpus are unchanged.
- **If your client handles web-search refusals by code**, an unsupported argument is now refused as `search-argument-unsupported` and an out-of-form value as `search-argument-invalid`, each naming the argument, where before both were the unnamed `invalid-request`. Nothing is sent, charged or receipted on either.
- **If your host reads `adapter-sources --provider web-search --describe-research`**, the description is now version 2: version 1's members with their meaning, and `requestSchemaVersion`, `resultSchema` and `resultSchemaVersion`. A reader that holds the description closed at version 1 refuses it: the Desk does until judgment-pack-desk#444 lands, so a Desk should not pin this release before then.
- **To restrict a Tavily search**, pass `includeDomains` or `excludeDomains` (1 to 20 domain names) or `timeRange` (`day`, `week`, `month`, `year`); a Google grounding connection refuses all three by name.

## Web-search arguments held to one table (#285, part of #275)

- One table per provider drives both the enforcement and the description's request schema, so the two cannot drift. Tavily takes `query`, `maxResults` (1 to 10), `includeDomains` and `excludeDomains` (1 to 20 distinct domain names of two or more lowercase labels, the last with a letter; at most 253 bytes each) and `timeRange`; Google grounding takes `query` and `maxResults` (still not sent to Google; the answer's grounding links are cut to it).
- A domain restriction is sent as a hard filter (`include_domains_mode: "restrict"` on every request carrying `includeDomains`), and the new arguments are named in the committed statement exactly as sent. Tavily filters a time range by publish or last-updated date and keeps results it cannot date; the schema says so.
- `--describe-research` writes description version 2 with `tavily-request-1`, `tavily-result-1`, `google-grounding-request-1` and `google-grounding-result-1`, each pinned by a test to its schema's digest; a schema change bumps its version.
- ADR-0019 records the decision (accepted with this release). Google documents `exclude_domains` for its search tool; it stays refused by name until observed (ADR-0019, option D).

## An acquisition fixture for consumers (#290)

- An explicit `gateway_acquisition_fixture` build supplies fixed HTTPS transport to the existing page and search acquisition code and records their real acquisition envelopes through the unchanged signer, so a consumer can test portable research deterministically. Its program lives under `adapters/testdata`; ordinary adapter builds and the release archives exclude it.
