Two changes, both off until an operator turns them on. A document processor (OCR) can be chosen for the scanned pages of uploads, Drive files, S3 files and public PDF links: local Tesseract, a program from the OCR tools bundle, or one of three cloud services. A web-search connection can be given a longer timeout, and a search that runs out of time now says so. With neither configured, the local plan this gateway serves is `v0.9.1`'s byte for byte, so every released Desk keeps taking it; nothing that started under `v0.9.1` refuses to start, and no receipt, registry or policy format changes.

## What an operator must do

- **Nothing**, unless OCR or a longer search timeout is wanted.
- **To read scanned pages**, choose a processor through the connections companion (`gateway-connections --provider document-processing`, operations `status`, `configure`, `test`), or through Desk once its document-processing release ships. A cloud processor needs that vendor's credential, entered once and never shown again. Turning a processor on or off changes the plan the gateway serves, so a local gateway started under the old plan is restarted to take it.
- **To let a search take longer**, set `timeoutSeconds` (10 to 120) on a web-search connection; 45 remains the default.

## Choose a document processor for scanned pages (#218)

A `document-processing` companion provider keeps one settings file per principal in the connections store, under the store's rules: file `0600` in `0700` directories, owner checked, no link followed, written by atomic replace under the store's lock, at most 64 KiB, and validated on every read by the rules it was written under; a credential that no longer validates makes the settings unreadable, not empty. `configure` is a compare-and-swap on the file's SHA-256. The processors: off (the default), `tesseract`, `program` (an absolute path inside the OCR tools bundle beside the executable or `/usr/bin`, resolved after symlinks; any other path is refused), Google Document AI, Azure Document Intelligence (prebuilt-read) and Amazon Textract (DetectDocumentText), with a processing deadline of 10 to 120 seconds.

- **Where the credential goes.** `status` and `configure` answer only that one is held. The workers write nothing to stderr and every error is a fixed token. The credential travels in a header, never a URL. Each page's text, as decoded and in the form a record takes, is held against every secret the settings hold before it is returned, so a reply that echoes a secret is refused. The settings' revision reaches the cloud worker in its environment, not as an argument. A record names the processor's kind and the program's file name and digest, never a directory on the host.
- **Where the document goes.** `tesseract` sends nothing anywhere; `program` runs the operator's program on this host; a cloud processor sends one PNG per page needing OCR to that vendor's documented endpoint and no other: no redirect followed, no proxy, a 120 s client deadline, response headers at most 64 KiB, a reply at most 8 MiB, a page image at most 5 MiB. Azure's result is polled at a URL rebuilt from the result's identifier alone. No processor falls back to another.
- **The local worker.** Poppler's `pdftoppm` and Tesseract are run by absolute path from the bundle or `/usr/bin`, never `PATH`, through bounded pipes, with no shell and no temporary file; the bundle's library path is given only to the bundle's own programs. A worker or tool that is missing stops the read with `processor-not-installed`; "could not read the settings now" stops the read and is never "OCR off". The companion's `test` runs its worker in its own process group, ended whole at the deadline.
- **The plan.** With the processor off, `--local-plan` is `v0.9.1`'s byte for byte. With one configured, `documents`, `drive`, `web` and `aws-s3` are given 150 s, the connections directory and the `--document-processing` launch flag; only adapters launched with that flag apply the settings.

What it establishes: which program read a page, under which settings revision, as the adapter's testimony under the page-text contract, which `attachment.Check` holds to the pages declared as OCR. What it does not: that a page had no text layer; anything about a cloud vendor's handling of the page once sent.

## Let a search take longer, and say when it ran out of time (#219)

A web-search connection carries `timeoutSeconds` (0 for the default of 45, else 10 to 120), checked at `configure`, on read-back and where the request's deadline is set. The companion's `status` advertises the bounds (`defaultSeconds` 45, `minSeconds` 10, `maxSeconds` 120), which Desk reads before it shows the field. A search that reaches its deadline answers `search-timeout`; before, a slow Google token exchange was reported as `credentials-required` and a slow provider as `provider-unavailable`. The search client no longer cuts the response headers off at 15 seconds; the connection's deadline bounds the whole request. While no connection's timeout exceeds 50 seconds the plan is unchanged; past that, `web-search` is launched with `--long-search` and 130 s. A stored timeout outside the bounds (a hand-edited or corrupted connection file) never selects the long plan and is reported as invalid rather than echoed; the choice of deadline (55 s without the flag, 125 s with it, 125 s for the companion's `test`) is tested on the context each branch returns. Writing the token-exchange test found that a timed-out Google token exchange was reported as `credentials-required`; it is now `search-timeout`.

## Verification

CI ran the Go suite on Linux, macOS and Windows, the adapters, the engine image, the release-contents check (which now covers the two new programs, `ocr-tesseract` and `ocr-cloud`), both plugins and `verify-ts`, and `gateway conform` reported no disagreement with the corpus.

- **Mutation checks:** #218, 15 single-change variants of the ported safeguards and 13 of the review's fixes, each caught by a named test; #219, 14 and 11 of the review's fixes; the records are in the pull requests.
- **Review:** one adversarial round each, recorded on #218 and #219 with the reviewed commit, the reviewer's vendor, a stated deviation from the review rule (the working copy was drafted with one vendor's model and ported with another's, so no third was available) and a disposition for each finding. #218: three HIGH (an escaped echo of the credential reaching a record; a bundle symlink escaping containment; Azure's polling URL carrying the key) and three MEDIUM, all fixed in the same pull request. #219: two MEDIUM (a stored out-of-bounds timeout driving the plan; the deadline selection untested), both fixed in the same pull request, and a defect the added tests found (a timed-out token exchange reported as `credentials-required`), fixed too.

Not exercised: a real call to any cloud vendor (no credential on the build machine; the request shapes follow each vendor's documentation and stand-ins); a real Tesseract or Poppler run (stand-ins by design); the OCR tools bundle's layout on macOS and Windows (on Windows the workers build but cannot find their programs); Desk's client of the processing wire, which is not released yet; a replacement of a program's file between its check and its start.
