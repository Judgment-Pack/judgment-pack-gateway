Gateway v0.17.0: a decision policy may hold a container's shape (`shape`, engine configuration version 10), so a closed policy admits one shape of request; the connection catalog's version 4 names the program each eligible source's receipts are written by; an operator can describe a web-search connection's exact research binding without acquiring anything.

## What an operator must do

- **Nothing for an existing configuration.** A file of engine configuration version 9 or earlier keeps its meaning, and every policy in it keeps its digest, byte for byte; `connect` raises no version. Acquisition, receipts and the version-2 and version-3 catalogs are unchanged.
- **If you run the worked Azure DevOps write-back policy, or a closed policy whose pointers continue through an array index**, move the file to version 10 and add `shape`. Under version 9 such a policy also admits the request with that array written as an object whose members are named `"0"`, `"1"` and so on (RFC 6901 reads a numeric token on an object as a member name); v0.16.0's documents state that limit. The rewritten worked policy in `docs/design/engine-config.md` holds `/updates` to an array of at most two, and with its two fixed elements to exactly two.
- **An installation that publishes an unbound operation** (RFC 0018 §4.4) copies the catalog's new `adapter` member into the operation's `record`, never the catalog's `record`; only sources of shape `airbyte`, `mcp` or `http` carry it.

## A policy holds a container's shape (#282, closes #267)

- A decision policy may carry `shape`, entries of exactly `{pointer, type: "object"}` or `{pointer, type: "array", maxLength}`, `maxLength` an integer from 0 to 524288. The value at the pointer must be there and of that type, and an array no longer than the bound; an absent value is refused as `fix` refuses one. A pointer may be both bound and shaped, never shaped twice or both fixed and shaped. The two refusals name the pointer only, never the value, the type found or the length.
- `policy-bind` holds `bind`, then `fix`, then `shape`, then `closed`. For `closed`, a shaped pointer reaches its container and covers nothing under it: a member below still needs `bind`, `fix` or another `shape`.
- `shape` is a member of engine configuration version 10. A file of version 9 or earlier that carries it, even `"shape": []`, is refused by name; version 11 is unknown. `action.policy` is still the digest of the policy as configured, members with it; `maxLength` is the policy's only number and has one canonical spelling. The verifiers read `action.policy` as a digest only and are unchanged.
- ADR-0018 records the decision (accepted with this release). ADR-0016 is not edited: its index row names ADR-0018, which qualifies its sentences on the empty arguments object, the policy holding no number and the container type. `SPEC.md` §1.2a, `SECURITY.md`, the engine-configuration and executor designs and the READMEs say the same. The version-9 admission of the object spelling is kept as a regression test under a policy without a shape.

## The catalog names each source's program (#280, closes #279)

- Catalog version 4 gains `adapter` on each provider's `source` contract and each `sources` entry whose shape an unbound operation can have (`airbyte`, `mcp`, `http`): the program the source's receipts name in `adapter.name`, taken from each adapter's receipt-minting code (`adapter-drive`, `adapter-gmail`, `adapter-sources`, `adapter-web`). The two command-shaped sources, Obsidian and S3, carry none, because their receipts name the configured command. An empty or unknown program is refused by name and no catalog is made. Versions 2 and 3 are byte-identical to v0.16.0's.
- ADR-0017 and the connection catalog design state the difference between `record`, a result contract, and `adapter`, the program a published dialect's `record` names (judgment-pack-spec#184).

## Describing a research binding without acquiring (#281)

- `adapter-sources --provider web-search --describe-research`, operator-only, prints for the current connection revision the executable's identity, the endpoint, the declared capabilities, the fixed arguments and the request schema, so a host can register a portable research binding without guessing them. It acquires nothing, charges no allowance and emits no credential. Endpoint construction is shared with acquisition; requests, receipts, policy checks and allowance enforcement are unchanged. The host still reviews and registers its profile through the Runner.
