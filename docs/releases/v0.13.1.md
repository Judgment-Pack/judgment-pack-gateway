Two changes, one of them to the remote form of `adapter-mcp` shipped in `v0.13.0`: each answer of a remote MCP server is now held to a bound of its kind on the bytes as received, before anything is parsed, and the remote form's transport no longer decompresses an answer, refusing any content encoding but `identity`. The other is a test fixture. Nothing that started under `v0.13.0` refuses to start, and no record changes.

## What an operator must do

- **Nothing.** No configuration, policy, receipt, registry or connection format changes. An answer a remote server compresses, or sends above its bound, is now refused before it is read in, where `v0.13.0` read it in first; the connection providers (Databricks, Azure DevOps, Notion) keep their own bounds and transports exactly as they were.

## Bound each answer of a remote MCP server by its kind before it is parsed (#263, closes #250)

- The HTTP MCP client takes a limit per kind of answer, each on the whole body or event stream as received: a tool call at `--max-output` plus 64 KiB of envelope, `initialize` at 1 MiB, each `tools/list` page at 8 MiB, and `--max-output` plus 64 KiB for any other kind; zero leaves the client's old single bound, which is what the connection providers pass. An answer at its limit is read, one byte past is refused before parsing with the method and the bound named and nothing of the body; an oversized line of an event stream is refused the same way. A JSON body is read whole before parsing; an event stream is held to its limit as a whole and per event, parsed as it arrives, and the response ends the reading. The remote form's transport sets compression off and refuses any `Content-Encoding` but `identity`, every header value checked, before anything is read; the connection providers' transports are untouched.
- Tests: bodies at the bound and one past for a call, the handshake and a listing page, with chunked bodies that carry no length; fragmented, multi-event and trailing-data streams; an oversized line; a gzip body, a `br` header and an upper-case `GZIP` header each refused with one request made and no `Accept-Encoding` sent; the stdio form's golden records, `TestRemoteOutputBound` and the providers' tests unchanged.
- What it establishes: a remote server cannot make the adapter read more than the bound of the answer's kind before the adapter refuses it. What it does not: anything about an answer within the bound; the result bound after parsing is unchanged.

## Hold every Databricks MCP safeguard test to the configured path (#262, closes #254)

Test-only. The safeguard fixture compared a request's path with the configured one only under `/api/2.0/mcp/`, so the Unity Gateway cases never ran that assertion. It now compares every MCP request's escaped path for all five server kinds, and a test gives each kind a wrong expected path and asserts the fixture reports the real one.

## Verification

CI ran the Go suite on Linux, macOS and Windows, the adapters, the engine image, the release-contents check, both plugins, `verify-ts` and the end-to-end scenario at each pull request's head; `gateway conform` is unchanged by either change. No live server was contacted.

- **Mutation checks:** #263, 9 mutants in scratch copies (4 in the build: the check moved after parsing, the handshake limit dropped, the listing limit dropped, the call overhead tripled; 5 on the review's fixes: compression re-enabled, the encoding refusal dropped, the cumulative stream bound dropped, the scanner's error ignored, the kind dropped from the refusal), each compiled and caught by a named test, and one shown equivalent (the per-event bound, subsumed by the cumulative one). #262: a Unity Gateway request routed to another `/ai-gateway/` path, caught by the new fixture and missed by the old.
- **Review:** #263, one cross-vendor round (OpenAI model, medium effort, read-only, at ea55d60): one HIGH (the transport decompressed gzip before the limiter saw the body), one MEDIUM (the docs claimed the whole stream was held before parsing) and two LOW, all fixed in the same pull request at f931e7a with the reviewer's probes adopted as regressions. #262: test-only, no review round.
- **Not exercised:** a real remote server; a concatenated-gzip body, since the encoding is now refused unread.
