# v0.41.0 (draft)

This draft states what ships in v0.41.0.

## Engine configuration versions

No new engine configuration version and no PostgreSQL migration. A configuration that runs on v0.40.0 behaves as it did there, except as stated below.

## Refusal-entry forwarding

Follow-ups to the refusal-entry forwarding source (ADR-0059 section 9, #611). No answer, receipt or entry changes, and the sink is sent what it was sent before.

- **On the PostgreSQL kind, a forwarding pass takes no pool connection.** The forwarding cursor's
  read, and its compare-and-set under the journal's advisory lock, now run on the source's own
  connection, the one it reads entries and takes the lock on, and no longer on the pool that answers
  use. The compare-and-set is a statement of the transaction that holds the lock, so `remove-scope`
  can no longer take a journal and its cursor between the lock and the cursor's move. Before, where
  the pool stayed saturated past the idle bound, that could leave a cursor naming an entry no journal
  holds, and forwarding of the scope's next journal stopped at it, named once on stderr. No
  transaction is open across a delivery.
- **One read of a journal per forwarding pass.** A pass reads the entry at the cursor and the batch
  after it in one read, on both kinds. On the filesystem kind a pass starts where the journal's
  last read ended, once it has checked that the file is the same one and still holds that line,
  so a pass over a journal that has not changed reads no entry past the cursor's; a file replaced,
  cut back or rewritten is read whole, as before. The source keeps one line for each configured
  journal.

## Refusal journal operations

- **A staged key file of any journal's name is removed** (gateway #611). The start removes,
  before any key is read, every staged key file a start ended mid-draw left in the store's root
  (`.<journal>.key.<pid>.<12 lowercase hex>.tmp`), whatever journal it names. A scope no longer
  configured no longer leaves its file behind. Only a regular file of exactly that form is
  removed: never a link, a directory or a near miss, and never one carrying the start's own
  process identifier. `gateway remove-scope` of a scope also removes that scope's staged files and
  says so on stderr. A staged file holds a key no entry was ever made under, so nothing is lost.
- **A way out for the refusal journal of the sources of no scope** (gateway #611). Where that
  journal's key is lost, as after a restore from a full export, which carries no keys,
  `gateway journal reset --config <file> --unscoped --by <label>` (filesystem) and
  `gateway store journal-reset --unscoped` (PostgreSQL, with the connection and role flags of the
  other store commands) remove that journal, its key and its forwarding cursor, with the gateway
  stopped. They take no scope argument: `--scope`, or any other argument, is a usage error.
  Before anything is removed they write a signed operator entry of the new kind
  `refusal-journal-reset`, naming the journal's bytes by `refusalJournalBytes` and
  `refusalJournalDigest`; `gateway verify` and verify-ts read it alike, and two corpus vectors,
  `v3-journal-refusal-journal-reset` and `v3-journal-refusal-journal-reset-half`, hold it. No
  receipt, session, removal record or other journal is touched. The next start draws a new key and
  journals the refusals of the sources of no scope again. A filesystem run cut off after its entry
  is completed by a second run or the next start. The manual step of moving `<name>.jsonl` aside on
  the filesystem kind is gone from `docs/design/store-contract.md`.

## Compatibility

- **The staged key files.** A v0.40.0 start removes only its configured journals' staged files;
  a later v0.41.0 start removes the rest. Nothing else in the store's root is touched.
- **The `refusal-journal-reset` entry.** A v0.40.0 `gateway verify` or verify-ts reads an operator
  journal holding a `refusal-journal-reset` entry as `journal-entry-forged` at that entry, as
  v0.39.0 read v0.40.0's `remove-scope` entry carrying the refusal journal's members. Verify such a
  store with v0.41.0 or later.
