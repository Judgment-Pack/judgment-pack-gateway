# v0.40.0 (draft)

## ES256 delegation statements

Part of spec RFC 0030's amendment of 2026-11-22 (*Signing with a P-256 key*). It takes one engine configuration version, 41 (a placeholder number, assigned in merge order), and no PostgreSQL migration.

- **The statement.** A delegation statement a P-256 key signs holds `alg: "ES256"` inside what it signs and digests, and its signature is `r||s` at low S. A statement an Ed25519 key signs is unchanged, byte for byte. The gateway verifies each link by the algorithm its `alg` names, under a key pinned with that algorithm, so a chain may mix the two link by link (SPEC.md §11.1).
- **The refusals** are the existing names: an `alg` other than the string `"ES256"`, and a DER-encoded signature, are `malformed`; a high-S signature is `signature-mismatch`; a link whose `keyId` names a pinned key of the other algorithm is `key-mismatch`.
- **The pin** (engine version 41): `delegation.hosts[].keys` takes `{"alg": "ES256", "key": <66 lowercase hex>}` for an issuing host's P-256 key, beside Ed25519 keys as strings, as `retention.acknowledgedBy` does. A bare 66-character string is refused, naming both forms; an unsound point is refused as `is not a sound P-256 public key`; before version 41 the object is refused by name (SPEC.md §11.2).
- **The cases.** `testdata/delegation/es256-statements.json` is a byte-for-byte copy of the spec repository's `conformance/delegation/es256-statements.json`: 55 cases of the amendment's tables 1 and 2, made once by Python's `cryptography` 44.0.0, independent of this repository, and frozen. The 39 Ed25519 cases of `testdata/delegation/statements.json` pass unchanged.

### What changes at every version

- A statement holding a top-level `alg` other than the string `"ES256"` was tolerated and signed with the rest; it is now `malformed`, as the RFC states.
- An Ed25519-signed statement holding `alg: "ES256"` verified before; it is now `key-mismatch`.

A statement that holds no `alg` keeps its verdict.

### Upgrade

Upgrade the gateways before an issuing host signs with a P-256 key, then pin the host's P-256 key at version 41 beside its Ed25519 key, and only then let the host sign with it. An earlier gateway refuses every ES256 link `key-mismatch`, and a version-41 file by its version.
