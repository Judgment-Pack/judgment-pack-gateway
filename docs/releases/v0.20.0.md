Gateway v0.20.0 adds separately authorized, revocable recurring Google Drive source reads through the private host connection pipe. A host can retain snapshots across restarts without extending a one-use picker grant. The build-tagged search acquisition fixture now validates requests through production's argument table.

## What an operator must do

- **Existing selections do not grant recurring access.** A compatible host must obtain explicit recurring consent for each resource. Catalog versions 3 and 4 advertise the new operations only for Drive; catalog version 2, research capabilities and model tools are unchanged.
- **Persist the bind request before dispatch.** Supply `operationId` (fresh unpredictable 32 bytes, encoded as 64 lowercase hexadecimal characters), `resourceId`, the current search response's `selectionContext`, and `consent: "recurring-read"`. A one-use selection grant is insufficient. Retry the exact request to recover its binding's current state, including revocation; a changed body under the same ID is refused. Independent operation IDs remain independently revocable.
- **Obtain new recurring consent after interactive reconnect/reconsent.** Successful same-account Drive reconsent revokes recurring bindings while preserving existing one-use picker/storage connection identity. Ordinary access-token refresh preserves recurring bindings. Disconnect, reconfigure and policy disable invalidate access.
- **Respect durable capacity.** The store permits 32 active bindings in the current generation and retains at most 48 operation records per installation principal, including revoked and old-generation records. Exhaustion returns `source-binding-limit`; identities are never evicted. Deleting custody is not a supported recovery procedure.
- **Keep host responsibilities explicit.** The host owns scheduling, retry/deduplication, history and policy decisions. Fence delivered observations against the current binding/generation before retaining them; Gateway provides no scheduler or observation-delivery outbox.

## Recurring source observations (#297, for #295)

`gateway-connections --provider google-drive` adds `source-bind`, `source-bindings`, `source-revoke` and `source-observe`. Bindings use separate private `source-bindings.json` storage, atomic replacement and the custody lock, without copying credentials.

Observations retain exact original bytes, the canonical checked attachment record, their digests and lengths, opaque provider revision, and recorded processor/configuration identity. Google-native documents retain exported PDF bytes. Original bytes are bounded at 4 MiB; observations at 16 MiB. Only `source-observe` has a 16 MiB + 64 KiB pipe reply limit. Partial extraction remains explicit; oversized replies are refused rather than truncated.

Authority is checked around provider I/O and after extraction. Revocation committed before final admission refuses the observation; later revocation cannot retract an already admitted response.

Coverage is `snapshot-only`, lifecycle `not-exposed`: no continuous coverage, intermediate revision history or external policy approval/withdrawal authority is established. Failures make no deletion or withdrawal assertion. Observations carry no signed Gateway receipt. SPEC, receipt meanings, signer boundaries and the frozen corpus are unchanged.

## Acquisition fixture correction (#296, for #293)

The search fixture now calls production's `readSearch` path. Tests compare request bodies, committed statements and refusal codes. It remains excluded from ordinary builds and release archives.
