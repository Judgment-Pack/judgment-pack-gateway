A decision policy can now fix an argument to a value and close the argument set (ADR-0016, accepted; engine configuration version 9), so a dispatcher write tool such as Azure DevOps's work-item tools is held to the write its decision means: a request that names another action, adds an operation or adds a member is refused before anything is sent. A remote MCP server's endpoint has one form, stated once in SPEC §1.2a and held alike by the adapter, the signer and both verifiers, with nine new corpus vectors; and no refusal of a binding's URL, a descriptors pin or a connect check repeats an endpoint's text any more, so a credential pasted into a path by mistake reaches no error. Configurations at version 8 and earlier load as before, and every released vector verifies as before.

## What an operator must do

- **Nothing**, unless a policy is to fix a value or close its argument set, or a remote binding's URL lies outside the one form. No receipt, registry, witness or connection format changes for anything configured before.
- **To hold a dispatcher tool to one write**, raise `engine.json` to `engineVersion` 9 and give the tool's `decisionPolicy` the two optional members: `fix`, an array of `{argument, value}` whose argument, an RFC 6901 pointer into the request's `arguments`, must be there and equal the value as a JSON value with its type; and `closed: true`, under which every member and array element of the arguments must lie under a pointer some `bind` or `fix` entry names. The engine never fills a value in: a request that omits or changes a fixed argument is refused at `policy-bind` with nothing sent, and the refusal names the pointer, never a value. The worked Azure DevOps policy in `docs/design/engine-config.md` fixes `action` to `update` and the revision test, binds the work item's `id` and the tested revision to the record, and is closed; the record no longer has to state the whole write. A version-8 file that carries either member is refused by name; `connect` keeps a version-9 policy as written.
- **Know what a closed policy establishes** (ADR-0016 §5; SECURITY.md): that the request's arguments were exactly those the policy names, each bound to the record or fixed by the policy, at the moment of the check. Not that the target interpreted them as intended, nor anything of what a policy does not name when `closed` is false. A closed policy holds the values it names and that nothing else is present; it does not hold the container type of an ancestor, so an object whose member names are an array's indexes is read as that array's elements (#267 asks whether a policy should hold a container's shape).
- **Check a remote binding's URL against the one form** if it was accepted before: at most 2048 printable ASCII characters; `https://` or `http://`; a host that is a name of `A-Z a-z 0-9 - . _` or an IPv6 address in brackets, then optionally `:` and a port from 1 to 65535 with no leading zero, then nothing or `/` and a path in which every `%` is followed by two hexadecimal digits; no `?`, no `#`, no user before the host; after `http://`, a loopback address written as one. The adapter now refuses a host with other characters or a percent escape, a `:` with no port, and an address in brackets that is no IPv6 address, each with its own reason; an `@` in the path is still a path character, as hosted registries write it. The catalog bindings and the documented examples are within the form. A record naming an endpoint out of the form is `malformed` in both verifiers.
- **Open as issues**: #267 (a policy holding a container's shape), #268 (`action.tool.endpoint` held to the same form for a remote write), #259 (the local Azure DevOps server as a catalog binding), #260 (the postgres binding's `execute_sql` write is raw SQL).

## A policy fixes a value and closes the argument set (#265, closes #258; ADR-0016)

- The two members read by the same strict parser as the others: an entry with a member beyond its two or without one, a pointer that is not a pointer, a pointer fixed twice, a pointer both fixed and bound, and `closed` that is not a boolean are refused. The check runs at the existing `policy-bind` step, after the bindings and before anything is sent; nothing else about the executor's order changes.
- The reach rule, arrays exactly: a pointer covers the value it names and everything under it; the empty pointer covers the whole arguments; an object or array on the way to a named pointer has each member or element held in turn; an array element is reached by its index pointer (decimal, no leading zero) or by a pointer that covers the array, so `-`, a leading zero and an element past those named reach nothing; a member's token is its one RFC 6901 spelling. A closed policy with neither `bind` nor `fix` admits only `{}`.
- `action.policy` is still the SHA-256 of the canonical form of the policy as configured, so the members change it as any member does; the receipt carries the digest only, and `verify`, `gateway conform` and the vectors are unchanged. SPEC §1.2a lists the members and their checks, and its remark that the policy's canonical form is also its RFC 8785 form is narrowed to a policy without `fix`. ADR-0011 carries a dated amendment beside its `bind` determination; ADR-0016 extends determinations 1 and 2 of ADR-0011 and supersedes nothing.
- After the review: the worked policy is described as admitting the illustrated request rather than only it, with the container-shape limit stated beside the example and in ADR-0016 §5; the reviewer's probe is kept as a regression that records the admission.

## One endpoint form across the adapter, the signer and both verifiers (#266, closes #251)

- Four implementations of one table, `testdata/remote-endpoints/cases.json` (44 accepted, 96 refused, every rule with a case on each side), read directly by a test in `go/`, in `adapters/mcphttp` and in `verify-ts`: the signer's `isRemoteEndpoint`, which `gateway verify`, the engine's binding, template and resolved-URL checks and the descriptors snapshot share; verify-ts's `isRemoteEndpoint`; and the adapter's `EndpointProblem`, which lost its `net/url` fallback and keeps a reason per rule. An address in brackets is an IPv6 address in the form RFC 3986 names `IPv6address`, with no zone, read with `netip.ParseAddr` in Go and a small parser in TypeScript that agreed on 300,011 generated candidates.
- Nine vectors under `corpus/v3/stores/`, signed with `TEST-SEED` by a scratch program that first re-signed every released remote receipt byte for byte: a malformed percent escape, an empty host, a host character outside the alphabet, an address in brackets that is no IPv6 address, an empty port, a port out of range, an endpoint of 2049 characters and `http://localhost:8080/`, each `malformed`; and one with a port and a well-formed escape, `ok`. The released vectors already hold a user before the host and a non-loopback `http`. Before this change, both verifiers graded the first five `ok`.
- ADR-0015 carries a dated amendment paragraph under "The form"; SECURITY.md and the adapters' README follow §1.2a's words.
- After the review: a refusal of a binding's URL, a template or a resolved URL names the binding, the operation and the rule and never the URL (the reviewer's probe: a path carrying a marker, ten `{tenant}/` placeholders and a 253-character value, refused past the form's length with the marker in the error); the sweep reached one more repeated text in the engine, the three descriptors-pin refusals and the two connect-check refusals, each now naming the endpoints it compares by role; a marker test triggers every one of them. An address in brackets was any run of hexadecimal digits, `:` and `.`, which the transport's URL parser refused later; it is now an IPv6 address in all four implementations, with a vector.
- Not changed: the path's alphabet admits every printable character but `?`, `#` and a bare `%`, so Go's client percent-encodes `"<>\^`{|}` on the wire while the receipt records the raw form, as before; the line `connect` prints for a check that holds still names the endpoint it reached, which is not a refusal.
