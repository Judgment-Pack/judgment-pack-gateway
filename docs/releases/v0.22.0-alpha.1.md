# Gateway v0.22.0-alpha.1

This alpha supplies owner-declared tool classifications and approval-bound MCP
metadata for Agent v0.11.0 integration. It also includes the merged receipt
construction and refusal-test changes since v0.21.0. It is a scoped prerelease;
it does not complete the final v0.22.0 or v0.23.0 milestones.

## Upgrade requirements

Current MCP admission requires binding version `2`, snapshot version `2` and
engine configuration version `11`. Version 1 bindings and snapshots remain
readable for historical inspection, but they cannot authorize current registration,
configured startup or unclassified tool offers.

For each enabled operation, declare `toolTaxonomies` for every exact allowed
server tool, update the pinned catalog explicitly and recapture using
`connect --replace`. Live and write operations have separate descriptor pins;
when both are enabled, both captures must succeed before replacing configuration.
Changed owner, endpoint, constraints or approved server metadata requires new
whole-byte approval and restart of the configured processes. Failed replacement
can leave unused immutable evidence; it is retained, not automatically deleted.

Request `gateway-connections --catalog-v5` for the new owner declarations and
complete derived profiles. The default and older catalog outputs are unchanged
and do not carry this contract. See the
[taxonomy migration guide](taxonomy-v2-migration.md) and
[ADR-0021](../adr/0021-owner-taxonomy-binds-current-tool-approval.md).

## Owner metadata and invocation

- Tool operation/effect declarations are mandatory on the current path; standard
  MCP hints derive from them. Server annotations that contradict the declared
  effect refuse admission. Names or model text never supply a missing declaration.
- The immutable owner declaration and descriptor snapshot are distinct pinned
  records. Each invocation verifies its operation's approval and the full approved
  tool projection before the selected call. Narrowing the execution allowlist
  does not discard drift checks on approved sibling tools.
- Catalog v5 preserves intrinsic operation families and the strongest effect of
  all constituents. Broker method profiles include their existing operator-policy
  reconciliation effect; arbitrary SQL and seal operations are classified as act.
- Metadata grants no execution authority. Existing acquisition, seal and action
  transport, approval and decision checks retain their meanings. A read-external
  label is not proof that a receipt signature was verified, and an uncertain action
  outcome does not permit an automatic retry.

Normative receipt contracts, frozen historical records and the conformance corpus
are unchanged. This alpha does not add signed descriptor provenance, generic
customer MCP registration, OS sandbox/posture support or uncertain-action
reconciliation. Their existing trackers remain open.

## Other included changes since v0.21.0

Receipt construction is shared across acquisition and action paths (#319).
Regression coverage pins canonicalization and receipt-shape refusals (#320),
receipt-directory filtering and session-token refusals (#322). Documentation
corrects the status of recurring Drive work (#321). The release also includes
merged development-kit, check-runner and public-text maintenance; those changes
do not establish new provider or workflow capabilities.

Pin the exact alpha version and verify its archives, checksums and attestations
as described in [releasing](../releasing.md). This prerelease is not marked latest.

historical records and make any future approval/pin migration explicitly.
