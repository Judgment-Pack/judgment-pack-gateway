# v0.35.0

This release adds one binding-format member, and one decision record that is accepted but not yet built. **It changes one answer for every `http` binding:** an endpoint's `403`, and its `401` where no token step obtained the token, is now answered `403 source_access_refused` where v0.34.0 answered `400` (item 1; ADR-0047).
- A binding may declare `operations.live.errorCodes`. It is a closed list of the endpoint's error codes:
  - those that mean an expired reference, answered `410 source_reference_expired`;
  - those passed on with an access refusal (item 1).
- The `microsoft-graph` catalog binding declares such a list, so its digest changes (item 2).
- ADR-0048 is accepted: retention by a pinned acknowledgment, and store rotation. It is built in v0.36.0 (#535; item 3).

The implementation row is [#534](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/534). Beside it:
- ADR-0048 itself ([#533](https://github.com/Judgment-Pack/judgment-pack-gateway/pull/533));
- the review LOWs this release carried, ADR statuses and these notes (this pull request).

| A PostgreSQL store of v0.34.0 (schema version 6) | Is served as it is. There is no migration, and the schema is unchanged. |

| Older verifiers and the corpus | Unchanged. No vector is added or changed. |
| Receipts and stores written before this release | Keep their bytes and verify as before. |
| Judgment Pack Runner and other `/acquire` clients | Unchanged for a request that succeeds. Three refusing answers of an `http` source change (item 1): a refused read answers `403` where it answered `400`; a `400` or `404` the `microsoft-graph` binding declares an expired reference answers `410`; and a refusing answer past the output bound keeps its class (`403`, `410`, `429` or `503`) where it answered `400`, a token step's `401` past the bound now dropping the token as any `401` to an obtained token does. |
| The runtime in the engine image | Unchanged: the `Dockerfile` pins `0.46.0`. The image and the release archives carry the changed `adapter-http`. |
| PostgreSQL | 16 is the version tested, in CI's two `postgresql` legs. |

## Changes for operators upgrading from v0.34.0

1. **A refused read is a `403`, for every `http` binding** (#534; ADR-0047).
   - **What changed.** An endpoint's `403`, and its `401` to a request that carried no token a token step obtained, is answered `403` with `code` `source_access_refused`. The answer carries `endpointStatus`, the endpoint's status, and `endpointCode`. `endpointCode` is the endpoint's error code when the binding lists it under `errorCodes.accessRefused`, and `unlisted` otherwise. v0.34.0 answered `400` with a sentence carrying the status.
   - **This holds for every `http` binding, whether or not it declares `errorCodes`.** A binding that declares none answers `endpointCode` `unlisted`.
   - **What does not change:**
     - A source's `401` to a token its token step obtained is still `TokenRejectedBySource`, answered `400` with the token step's sentence.
     - A token endpoint's `401` is still a refused token request.
     - Nothing of the endpoint's body is passed on beyond a listed code.
     - The answer is not receipted, and the session is left open.
   - **What to do.** A caller that matched the `400` sentence for a refused read now reads `code` and `endpointStatus` on the `403`.
   - **An answer past the output bound.** A refusing answer larger than the source's output bound is classed by its status all the same, with no code read from it. Only a success past the bound is refused for its size (this pull request; #534's L1).
2. **The `microsoft-graph` binding's digest changes** (#534).
   - **Why.** It now declares `errorCodes`:
     - `syncStateNotFound` and `resyncRequired`, beside `400` and `404`, as expired references;
     - `Authorization_RequestDenied` alone as an access code.
   - **If your configuration pins the shipped catalog's file,** re-pin each platform on that binding after upgrading. The start refuses the old pin by name until you do.
     - With one platform on the binding, `gateway connect --replace` for it does this.
     - With two or more, `connect --replace` refuses each time, since it still resolves the other platforms' old pins (#542). Edit the configuration by hand instead: set every platform's `binding` to `microsoft-graph@sha256:<digest>`, where `<digest>` is the lowercase hex SHA-256 of the new `catalog/microsoft-graph.json` (`sha256sum` prints it), then start.
   - **If you keep your own copy** of the binding in a catalog directory of your own (`catalog/README.md`), there is nothing to do. Your copy's bytes, and so its pin, are unchanged. To take the new list, add `errorCodes` to your copy. Its digest then changes for every platform pinning it, so re-pin them as above: `connect --replace` with one platform, the hand edit with two or more.
   - **An access code beyond the shipped list.** A code your deployment needs that the shipped list does not hold goes in your own copy, not the shipped file.
3. **Retention and store rotation are decided, not built** (ADR-0048, accepted; #535).
   - **The decision:**
     - a sealed session is removed only once a line signed under a key the operator pins names its seal, and the configured window has passed;
     - stores are rotated by `gateway store rotate`.
   - **Nothing in this release** removes or rotates anything. The build, its configuration members and its SPEC change come in v0.36.0.

4. **`adapter-http` itself** (#534), for an operator who runs it outside the gateway:
   - three new flags: `--error-code-at`, `--expired-codes` and `--access-codes`, which the gateway passes from a binding's `errorCodes`;
   - an endpoint's `403`, and its `401` where no token step obtained the token, now exits `10` with a report on stdout naming the status and the code (or `unlisted`), where it exited as a failed read before.

## Decisions

- **ADR-0047** (#534), accepted: an endpoint's error code is read from a closed list the binding declares, and a `401` or `403` is answered as an access refusal.
- **ADR-0048** (#533), accepted by the maintainer: retention by acknowledgment (A1), ADR-0034's session-removal record alone (R1), and rotation by an operator's command with a continuation line (S2). The build is #535.

## What this release does not establish

- That the live directory service answers the codes the `microsoft-graph` binding lists as the stand-ins do. Every test runs against an in-process stand-in.
- Retention and rotation, which are decided but not built.
- Of what v0.34.0 did not establish, these stand:
  - that anything of version 33 meets the live services as the stand-ins do;
  - that PS256 is taken by the live identity platform;
  - that a `read-external` tool only reads.
  v0.34.0's item on a refused `401` or `403` is closed by item 1.
- Federation, throttling of the list call and refresh failures stay in #492. #440, #444, #447, #450 and #474 stand.
