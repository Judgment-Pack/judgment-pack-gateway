One change. A public HTTPS source snapshot no longer follows a redirect to another origin: every hop is held to the origin the operator selected (`https`, the same host, port 443) before it is followed, and a hop elsewhere is refused with `web-redirect-origin` before any further request is sent. Before this release, the manual redirect loop followed a `Location` to another host, so a chosen public server could make another host's response the snapshot. A gateway configured as before keeps its receipts, registry, policies and connections, and nothing that started under `v0.10.0` refuses to start.

## What an operator must do

- **Nothing.** No configuration, policy, receipt, registry or connection format changes. A source whose server redirects to another origin is now refused rather than followed; its discovery reports the refusal as `blocked` with the new reason.

## Hold a web source's redirects to the selected origin (#224, closes #221 and #222)

- `readWith` compares every `Location` with the selected origin on the parsed URL the next request would use — scheme, host and port — and refuses a difference with the fixed token; the six-request bound is unchanged, and the private-range and DNS refusals still apply to a same-origin hop.
- Tests: a cross-host, a subdomain, an `http`, a `:8443` and a scheme-relative `Location` are each refused with exactly one request sent; same-origin redirects are followed within the bound; an unknown-length body is read only to the bound without waiting for the end of the stream (#222).
- What it establishes: the bytes of a snapshot came from the origin the operator selected, or from no one. What it does not: anything about that origin's content; the elapsed-time and header-size safeguards still have no discriminating tests (#223, open).

## Verification

CI ran the Go suite on Linux, macOS and Windows, the adapters, the engine image, the release-contents check, both plugins and `verify-ts`, and `gateway conform` reported no disagreement with the corpus.

- **Mutation checks:** removing the origin check fails the cross-origin test; replacing the bounded body reader with a whole read fails the #222 test; both by assertion.
- **Review:** one adversarial round recorded on #224 with the reviewed commit, the reviewer's vendor and a disposition for each finding (two MEDIUM findings — equivalent IPv6 origins compared as text; the body-bound test imprecise — fixed in the same pull request). The defect itself was found by the cross-vendor record made on #148 after its merge.
