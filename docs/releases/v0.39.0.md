# v0.39.0 (draft)

This draft is started from ADR-0054's "What the release notes must say". It states what is built so
far; the items under "Not yet served" land with the `/act` surface and are listed so that none is
left out of the final notes.

## Built

- **Approval citations in the format.** An action receipt may carry `action.approvals`, 1 to 8
  `{kind, id, digest}` entries, `kind` `"single"` or `"standing"` (SPEC.md §1.2a). Each entry is the
  requester's claim, checked for form only. v0.38.0 verifies such a receipt `ok` and shows no
  approvals.
- **The dry-run receipt** (SPEC.md §1.2c) is signed under `judgment-pack-gateway/dry-run/1:` and is in
  no session and no store. It is checked with `gateway verify-dry-run` or verify-ts's `verifyDryRun`,
  whose reports carry `dryRun: true`. Every receipt verifier, including v0.38.0, calls it `malformed`.
  It says nothing about the action key.
- **The new observation is `approval-cited-again`**, on an action receipt that cites a single approval
  another action receipt of the store also cites.
- **The read-back scope check.** A read-back resolves its action only where both carry the same
  `scope`, or neither does; otherwise `action-reconciliation-unresolved`. v0.38.0 does not make this
  check, and no gateway mints such a pair.
- **Corpus.** Ten `v3/stores` vectors for approvals and a new `dry-run` family of eight vectors, each
  recording v0.38.0's verdict.
- **The operator journal** (ADR-0056, #543), on the filesystem kind. From engine version
  `operatorJournalVersion` (`<assigned at merge>`), and on any store that already holds the journal,
  `retain`, `remove-scope`, `remove-artifact`, `seal-open` and `store rotate` (in the store rotated
  from) each write one signed, chained entry to `journals/operator.jsonl`. A `retain` entry holds the
  SHA-256 of the acknowledgment file and the configured key ids, so both are read back from the store.
  A removal's entry is staged in `journals/operator.pending` and committed after its records; the
  next journaled command settles a staged entry, and the start names one on stderr and serves.
- **`gateway verify` step 9.** New findings `journal-entry-forged`, `journal-order`,
  `journal-entry-mismatch` and `journal-entry-missing`; `journal-missing` under the new option
  `--require-journal <name>`; the new observation `journal-from`. A store with no journal is reported
  exactly as before.
- **Export.** A full export carries `store/journals/operator.jsonl`; an export by scope carries none.
- **Older readers.** A verifier of v0.38.0 passes `journals/` over: it does not check the journal, so a
  forged or missing journal goes unreported by it, and it refuses `--require-journal` as a usage error.
  `gateway export --check` of v0.38.0 refuses an export that holds the journal: `manifest: a file is
  not one an export writes`. Roll commands back to v0.38.0 only with the version lowered on a store
  that holds no journal.

## Not yet served

- The operator journal on the PostgreSQL kind (`store retain`, `store remove-scope`, `seal-open` and
  `store rotate` there), the `store-continued` entry in the store rotated to, and the journal's check
  in verify-ts and the corpus.

- From engine version `<assigned at merge>`, a platform may set `scope` with `write: true`. It then
  needs `identity.callerScopes` as an object and its own `decisionRecords`. `/act` then takes `scope`
  as `/acquire` does, and its receipts carry `scope` and `scopeSalt`.
- A scoped action's key is a different key from the same key in another scope or in none. A
  re-created scope starts with no keys. `remove-scope` removes the scope's journal and refuses while a
  key there is pending.
- A scoped action cites only receipts of its own scope.
- `/act` takes `"dryRun": true` and answers `{dryRun, request, salts}`, with no `receipt`. Under a key
  service each dry-run is one signing call.
- `/act` takes `approvals`, which the receipt carries as `action.approvals`.
- A key reserved with approvals is refused `action-journal-invalid` by an earlier release. Settle such
  keys before a rollback.
- `/act` has new `refusedAt` values, `dry-run` and `approvals`, and a body-level `scope-identifier`
  that answers `400`. The pre-body `scope-identifier` keeps its `403`.
- The specification side is judgment-pack-spec v0.6.1, and `specVersion` is 0.6.0, unchanged.
